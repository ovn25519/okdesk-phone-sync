# okdesk-phone-sync

Демон, который периодически заполняет дополнительный атрибут заявки Okdesk
номером телефона контакта этой заявки.

## Задача

Телефон контакта есть только в карточке контакта и не отображается в свойствах
заявки. Сервис заводит в заявке дополнительный атрибут (например, «Телефон») и
автоматически переносит в него номер телефона контакта: сначала `mobile_phone`,
затем `phone` (порядок настраивается). Номер нормализуется к виду `+7XXXXXXXXXX`.

Если у контакта телефона нет (или контакт вообще не заведён), сервис может
поискать номер в описании заявки — эта возможность включается параметром
`sync.search_in_description` и по умолчанию выключена.

Сервис обрабатывает только открытые заявки с **пустым** атрибутом; заявки, где
атрибут уже заполнен, не перезаписываются (проход идемпотентен).

## Как это работает

Один проход демона:

1. Проверяет (если включён `verify_attr`), что атрибут `phone_attr_code`
   присутствует в схеме дополнительных атрибутов заявок.
2. Запрашивает страницами открытые заявки с пустым атрибутом:
   `GET /api/v1/issues/list` с фильтрами `status_codes[]`, серверным фильтром
   `custom_parameters[phone_attr_code]=#null` и полями
   `fields[issue]=id,title,status,contact,parameters`. Серверный фильтр
   позволяет Okdesk вернуть только заявки с незаполненным атрибутом — лишние
   заявки не перебираются.
3. Для каждой заявки получает контакт (`GET /api/v1/contacts/?id=`) и выбирает
   телефон согласно `phone_priority`. Выбранный номер нормализуется к виду
   `+7XXXXXXXXXX` (например, `79207939333` → `+79207939333`). Контакты
   кэшируются в рамках прохода.
4. Если у контакта телефона нет, а включён `search_in_description`, запрашивает
   карточку заявки (`GET /api/v1/issues/{issue_id}`), извлекает из описания
   первый телефон и нормализует его к виду `+7XXXXXXXXXX`.
5. Записывает найденный телефон в атрибут заявки
   (`POST /api/v1/issues/{issue_id}/parameters`).

Локальная перепроверка «атрибут пуст» выполняется и на стороне сервиса: если
серверный фильтр вернёт заявку с уже заполненным атрибутом, она будет пропущена.

## Граничные случаи

| Ситуация | Поведение |
| --- | --- |
| У заявки нет контакта | заявка пропускается, пишется предупреждение в журнал |
| У контакта нет ни `mobile_phone`, ни `phone` | заявка пропускается, пишется предупреждение |
| Телефон контакта в нестандартном формате | нормализуется к `+7XXXXXXXXXX`; если формат не распознан, записывается как есть |
| У контакта нет телефона, но `search_in_description = true` | номер ищется в описании заявки; если найден — записывается |
| Номер не найден ни у контакта, ни в описании | заявка пропускается, пишется предупреждение |
| В описании несколько номеров | берётся первый по позиции в тексте |
| Контакт не найден | заявка пропускается, пишется предупреждение |
| Атрибут уже заполнен | заявка пропускается без изменений |
| Ошибка на одной заявке | фиксируется в журнале, проход продолжается |
| Ошибка 5xx или сеть | запрос повторяется с экспоненциальной задержкой |

## Сборка

Требуется Go 1.24+.

```sh
make build      # бинарник okdesk-phone-sync в корне проекта
make test       # модульные тесты
make vet        # статический анализ
```

## Настройка

1. В интерфейсе Okdesk создайте дополнительный атрибут заявки
   (Настройки → Дополнительные атрибуты заявок, тип «Строка»). При создании
   задайте машинный код атрибута — он понадобится в конфигурации.
2. Скопируйте `config.example.toml` в `config.toml` и заполните значения.

Ключевые параметры:

| Параметр | Описание |
| --- | --- |
| `okdesk.base_url` | базовый URL аккаунта, например `https://example.okdesk.ru` |
| `okdesk.api_token` | токен API (секрет) |
| `okdesk.phone_attr_code` | машинный код атрибута заявки, который заполняется |
| `okdesk.status_codes` | статусы, считающиеся открытыми (по умолчанию `opened`, `inprogress`, `delayed`) |
| `okdesk.phone_priority` | порядок выбора телефона: `mobile_phone`, `phone` |
| `okdesk.verify_attr` | проверять атрибут в схеме на старте |
| `sync.poll_interval_minutes` | период между проходами (по умолчанию 5 минут) |
| `sync.dry_run` | режим примерки без записи в Okdesk |
| `sync.search_in_description` | искать телефон в описании заявки, если у контакта его нет (по умолчанию выключено) |

Файл `config.toml` содержит секрет — держите права `0600` и не добавляйте его в
контроль версий (он уже указан в `.gitignore`). Секреты маскируются при
логировании.

## Запуск

Один проход (удобно для проверки конфигурации и в режиме `dry_run`):

```sh
./okdesk-phone-sync -config config.toml -once
```

Демон:

```sh
./okdesk-phone-sync -config config.toml
```

Флаги:

- `-config` — путь к файлу конфигурации (по умолчанию `config.toml`);
- `-once` — выполнить один проход и завершиться;
- `-version` — показать версию и выйти.

Процесс корректно завершается по `SIGINT`/`SIGTERM`.

## Установка как служба systemd

```sh
install -m 0755 okdesk-phone-sync /opt/okdesk-phone-sync/okdesk-phone-sync
install -m 0600 config.toml        /opt/okdesk-phone-sync/config.toml
install -m 0644 deploy/okdesk-phone-sync.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now okdesk-phone-sync
```

Юнит перезапускает сервис при сбое (`Restart=on-failure`), поэтому временная
недоступность Okdesk на старте не требует ручного вмешательства.

## Проверка

В режиме примерки ничего не записывается, а в журнал выводится, что было бы
сделано:

```sh
./okdesk-phone-sync -config config.toml -once
```

Итог каждого прохода пишется в журнал одной строкой:

```
проход завершён dry_run=false found=12 updated=10 updated_from_text=3 would_update=0 would_update_from_text=0 skipped_no_contact=1 skipped_no_phone=1 skipped_has_value=0 errors=0 duration=1.2s
```

Признак корректной работы: после прохода у открытых заявок, где у контакта есть
телефон, атрибут заполнен; повторный проход не находит таких заявок и сообщает
`found=0`.

## Структура

```

internal/okdesk/                REST-клиент Okdesk
internal/phone/                 извлечение телефона из текста
internal/sync/                  логика проходов синхронизации
deploy/                         systemd unit
```
